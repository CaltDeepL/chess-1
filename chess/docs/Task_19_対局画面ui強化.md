# task-19 合法手ハイライト・エラー表示・スマホ対応

## ゴールと完了条件
- 駒を持ち上げたときに移動可能マスを表示する
- スマホ(375×812)で全画面が崩れず操作できる
- 完了条件: ドラッグ中のハイライト表示、モバイル実機幅での表示・操作が確認できること

## 設計判断の根拠
### 合法手ハイライトはフロントの `chess.js` で行う(バックエンドに専用APIを作らない)
当初 `GET /games/:id/legal_moves` をバックエンドに追加する案で実装を始めたが、以下の理由で**削除してフロント完結に切り替えた**。
- 手番が回るたびにAPIを1往復するのはレイテンシとして無駄
- **既存アーキテクチャとの矛盾**: 「合法手判定はサーバー権威、フロントは表示のみ」という方針に対し、独立エンドポイントは中途半端な二重化になる
- そもそもそのエンドポイントはコンパイルも通っていなかった(既存の `AppError` 型の使い方が誤っていた)

**結論**: フロントは `chess.js` で**表示専用**のハイライトを出す。実際の指し手検証は引き続きバックエンドの `shakmaty` が権威を持つ。表示と検証で別ライブラリを使うことになるが、フロントの誤判定は「ハイライトが出ない/余分に出る」だけで、不正な手は必ずサーバーが弾く。

## つまずいた点と教訓
| # | 症状 | 原因 | 対応 |
|---|---|---|---|
| 1 | **スマホでページが真っ白** | `index.html` の `<meta viewport>` が **`<head>` の外**に置かれており、ViteのHTML解析自体が壊れていた | `<head>` 内へ移動 |
| 2 | スマホでドラッグ中にページがスクロールしてしまう | `touch-action: none` が**実際には使われていないCSSクラス**に設定されていた | 実際の盤面要素に付け直し |
| 3 | 対戦相手名が長いと `.game-status-bar` からはみ出す | `flex-wrap` 未設定 | `flex-wrap` を追加 |
| 4 | 読み込み失敗時に「読み込み中...」から永久に進まない | `getGame` のエラーを握りつぶしていた | エラーメッセージ+ロビーへ戻るボタンを表示 |

- **教訓(#1)**: **実機幅で実際に開くまで気づけない**タイプの重大バグ。しかも原因はCSSではなくHTMLの構造だった。「スマホで崩れる」と「スマホで表示されない」は切り分けて調べる
- **教訓(#2)**: CSSを書いたつもりでも、**そのセレクタが実際にDOMのどの要素に当たっているか**は別問題。DevToolsで対象要素の computed style を確認する
- **教訓(#4)**: task-07 の「ログにしか出ないエラー」と同型。**握りつぶされたエラーはユーザーには無限ローディングとして現れる**
