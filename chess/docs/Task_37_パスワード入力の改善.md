## 設計判断の根拠

### 案内の文言を task-35 に合わせる
最小文字数を8→12に上げたが、**フォームの案内は「8文字以上」のまま残っていた**。要件を上げたのに案内が古いと、利用者は登録に失敗しても理由が分からない。

あわせて「記号や数字は必須ではない」も明記する。文字種を強制しない方針は利用者の直感に反するので、伝えないと `Password1!` 系を試し続けることになる。サーバーのエラー文言（`domain/password.rs`）と同じ内容を、失敗する前に見せる形。

### ログイン側に要件を出さない
既存ユーザーは12文字未満のパスワードでもログインできる（task-35 の判断）。ログインフォームに「12文字以上」と書くと、**自分のパスワードが要件を満たしていないユーザーが混乱する**。

### 絵文字ではなくインライン SVG
👁 は環境によって字形とサイズが大きく変わり、ボタンの当たり判定が揃わない。SVG なら寸法が固定で、`currentColor` によって配色にも追従する。外部アイコンライブラリを足す必要もない。

### `type="button"` を明示する
`<button>` のデフォルトは `type="submit"`。フォーム内に置くと**トグルを押しただけで送信される**。見落としやすく、押した瞬間に登録処理が走るので影響も大きい。

### `autoComplete` を呼び出し側から必須で受け取る
`new-password` と `current-password` を使い分ける。ブラウザとパスワードマネージャーはこの値で「保存するか」「補完するか」を判断する。**省略可能にすると付け忘れる**ので、必須の prop にした。

### アクセシビリティ
| 対応 | 内容 |
|---|---|
| `aria-label` | 状態に応じて「表示する」「隠す」を切り替える |
| `aria-pressed` | 現在オンかオフかを伝える |
| `aria-describedby` | hint を入力欄に紐づける |
| `aria-hidden` (SVG) | アイコンは装飾なので読み上げない |
| `useId` | 同じ画面に複数置いても id が衝突しない |
| タップ領域 40px | 小さいと押しづらい |
| `:focus-visible` | キーボード操作で位置が分かる |

### 表示状態をフォーム離脱時にリセットしない
明示的なリセットは不要。画面を離れればコンポーネントがアンマウントされ、次に表示されるときは非表示から始まる。

## つまずいた点と教訓

### CSS のコメントはネストできない
`global.css` に貼るスタイルを、丸ごと `/* ... */` で囲んだ形で用意していた。その中に日本語の説明コメント `/* ... */` が含まれていたため、**内側の `*/` で外側のコメントが早期に閉じ**、残りが宣言として解釈されて `}` が浮いた。

Vite が CSS のコンパイルに失敗して 500 を返し、**ページが真っ白になった**。

**`tsc` も `eslint` も CSS を見ない。** ビルド系のチェックは全部通るため、ブラウザで開いて初めて分かる。型システムがカバーしない境界の一例。

### `FormEvent` の非推奨化
`@types/react` が `FormEvent` を「実際には存在しない型」として非推奨にしていた。実体である `SyntheticEvent<HTMLFormElement>` に置き換えた。

### 貼り付け時の断片混入（6度目）
`<PasswordInput>` の JSX が、`LoginPage.tsx` では関数本体の途中に、`RegisterPage.tsx` では **`handleSubmit` の中**に貼られていた。後者は task-22 で `<MoveHistory>` が `handlePieceDrop` の中に入ったのと同じ形。

| # | タスク | 症状 |
|---|---|---|
| 1 | 序盤 | `state.rs` が別ファイルの内容に置き換わる |
| 2 | task-22 | JSX が関数の中に紛れ込む |
| 3 | task-28 | 「ヘルパーを追加」が既存関数の置換になる |
| 4 | task-33 | `App.tsx` のルート重複、`LobbyPage.tsx` の断片が関数外に |
| 5 | task-36 | `register` が `logout` に上書きされて消滅 |
| 6 | task-37 | JSX が `handleSubmit` の中に |

**JSX を含む貼り付けは、関数の内側に落ちても構文としては成立してしまう**（式として有効なため）。TypeScript も気づかない。貼り付け後の `git diff` 確認は、もはや省略できない手順。

### 副産物: 古い制約が消えた
`minLength={8}` が input に残っていたが、`PasswordInput` への置き換えで自然に消えた。**サーバーが12文字を要求しているのにブラウザが8文字で通す**状態だったので、案内文言だけでなく HTML 属性側にも古い要件が残っていたことになる。

要件を変えるときは、**文言・HTML 属性・サーバー検証の3箇所**を確認する。

```

2. クリックで平文表示 → もう一度で伏字
3. 案内が「12文字以上。記号や数字は必須ではない...」になっている
4. Tab キーでアイコンにフォーカスが当たり、Enter / Space で切り替わる
5. フォーカスリングが見える
6. トグルを押してもフォームが送信されない
7. /login でも同様に動き、要件の案内は出ない
8. 11文字で登録 → サーバーのエラーが表示され、画面の案内と矛盾しない
9. 375px 幅でアイコンが入力欄からはみ出さない
```

**4と6は見落としやすい。** マウスだけで確認すると、どちらも気づかずに通ってしまう。
